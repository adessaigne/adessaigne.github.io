G1, ZGC, Shenandoah, … Chez Java, ils sont gentils avec tous leurs GCs mais moi je choisis lequel ?

Introduction

Lors de ce talk je présente les différents GCs (Garbage Collectors) de Java.

Mon objectif est de montrer qu'ils ne sont pas si complexes à comprendre et que choisir le bon GC peut facilement améliorer les performances de son application.

Résumé des GCs

Serial GC
Le GC avec le moins d'overhead, il ne fonctionne que sur un seul thread. Il est idéal pour les petites JVMs ou microservices.
Parallel GC
Le GC le plus efficace mais ses pauses peuvent durer plusieurs secondes. Il est idéal pour le traitement de données ou de batchs.
G1 GC
Le GC généraliste avec des pauses de 200ms maximum. C'est le GC par défaut.
ZGC et Shenandoah GC
Ces 2 GCs sont concurrents, ils travaillent sans bloquer l'application plus d'une milliseconde. Ils sont très forts en latence mais ont un coût à l'exécution non négligeable.
Espilon GC
Ce GC ne nettoie rien. Il est idéal pour le serverless ou les processus de très faible durée de vie.

Quelques flags intéressants

  • -Xms et -Xmx pour configurer la taille de la heap, idéalement ils sont identiques
  • -Xlog:gc*:file=gc.log:time,uptimemillis pour générer les logs du GC
  • -XX:+UseLargePages pour utiliser de grands espaces mémoire dans le noyau
  • -XX:+AlwaysPreTouch pour initialiser la mémoire et non seulement la réserver
