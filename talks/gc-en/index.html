G1, ZGC, Shenandoah, etc. With all these GCs in Java, which one do I choose?

Introduction

In this talk, I present the different GCs (Garbage Collectors) available in Java.

My goal is to show that they are not that complex to understand, and that choosing the right GC can easily improve your application's performance.

GC Summary

Serial GC
The GC with the lowest overhead, it runs on a single thread only. It is ideal for small JVMs or microservices.
Parallel GC
The most efficient GC in terms of throughput but its pauses can last several seconds. It is ideal for data processing or batch jobs.
G1 GC
The general-purpose GC with pauses of at most 200ms. It is the default GC.
ZGC and Shenandoah GC
These two GCs are concurrent, they work without blocking the application for more than a millisecond. They excel at low latency but come with a significant runtime cost.
Epsilon GC
This GC doesn't clean up anything. It is ideal for serverless or very short-lived processes.

Some useful flags

  • -Xms and -Xmx to configure the heap size; ideally they should be set to the same value
  • -Xlog:gc*:file=gc.log:time,uptimemillis to generate GC logs
  • -XX:+UseLargePages to use large memory pages provided by the kernel
  • -XX:+AlwaysPreTouch to initialize memory upfront instead of just reserving it
